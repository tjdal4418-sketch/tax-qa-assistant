# 검증 방법

## 1. 비교 조건

| 조건 | 설정 | 측정하려는 것 |
|---|---|---|
| **A. 일반 AI** | 새 대화, 프로젝트 지침 없음, 법령 MCP 끔, 웹 검색 끔 | 학습 데이터만으로 답할 때의 정확도와 환각 |
| **B. 도우미** | 프로젝트 지침 적용 + 법령 MCP + 웹 검색 | 이 프로젝트가 만든 최종 결과물의 정확도 |
| C. MCP만 (선택) | 지침 없음 + 법령 MCP만 켬 | "도구만 연결하면 충분한가?"에 대한 답 |

C 조건은 선택이지만 넣는 것을 권장합니다. 프로젝트 출발점이 된 [자녀세액공제 사례](../case-studies/01-child-tax-credit.md)가 바로 C 조건에서 틀린 사례이기 때문에, "MCP 연결"과 "검증 절차 설계"의 효과를 분리해서 보여줄 수 있습니다.

## 2. 통제 변수

- **모델**: 세 조건 모두 같은 모델을 사용하고, 모델명을 결과 파일에 기록합니다.
- **기준일**: 모든 질문 앞에 같은 기준일을 붙입니다. 예: `(기준일: 2026년 10월 19일)`
- **질문 문구**: [questions.md](questions.md)의 문구를 그대로 복사해 사용합니다.
- **대화 분리**: 질문마다 새 대화를 엽니다. 앞 질문의 답이 다음 답에 영향을 주지 않게 하기 위해서입니다.
- **원문 보존**: 답변 원문을 `raw/{조건}/Q01.md` 형식으로 저장합니다. 채점 근거를 나중에 누구나 확인할 수 있게 하기 위해서입니다.
- **수행 기간**: 가능하면 하루 안에 세 조건을 모두 수행합니다. 그 사이 법령이 개정되면 비교가 무의미해집니다.

## 3. 정답 확정 절차

채점 전에 각 질문의 정답을 먼저 확정하고 `questions.md`의 "정답" 칸에 근거와 함께 적습니다.

1. 국가법령정보센터에서 해당 조문의 **기준일 시점 본문**을 확인합니다.
2. 같은 법령의 **최근 부칙**(적용례, 경과조치, 특례)을 확인합니다.
3. 연계 법률이나 시행령 위임이 있으면 함께 확인합니다.
4. 정답과 근거 링크를 적고, 확인한 날짜를 기록합니다.

AI 답변을 본 뒤 정답을 정하면 판단이 흔들릴 수 있으므로, 반드시 답변 수집 전에 정답부터 확정합니다.

## 4. 채점 기준

### 정답 점수 (문항당 0~2점)

| 점수 | 기준 |
|---|---|
| **2 (정답)** | 기준일에 실제 적용되는 결론이 맞고, 핵심 수치·요건에 오류가 없음 |
| **1 (부분 정답)** | 결론은 맞지만 중요한 예외·특례를 빠뜨렸거나, 수치 일부가 틀림 |
| **0 (오답)** | 결론이 틀렸거나, 개정 전 법·개정안을 현행처럼 답함 |

### 환각 유형 코드 (해당하는 것 모두 기록, 세미콜론으로 구분)

| 코드 | 유형 | 예시 |
|---|---|---|
| H1 | 구법·개정안 적용 | 이미 개정된 기준을 현행처럼 답함, 국회 통과 전 정부안을 확정처럼 답함 |
| H2 | 수치 오류 | 공제 금액, 세율, 한도, 연령을 틀림 |
| H3 | 조문 오류 | 존재하지 않는 조문 번호, 내용과 맞지 않는 조문 인용 |
| H4 | 링크 오류 | 열리지 않는 링크, 내용과 무관한 페이지로 연결 |
| H5 | 근거 없는 단정 | 출처 없이 단정하거나, 불확실한 것을 확실하다고 표현 |
| H6 | 요건 누락 | 부칙 특례, 연계 법률, 배제 요건을 빠뜨려 결론이 달라짐 |

### 보조 지표 (Y / N / NA)

| 열 이름 | 기준 |
|---|---|
| `citation_correct` | 인용한 조문 번호가 모두 정확하면 Y, 하나라도 틀리면 N, 조문을 인용하지 않았으면 NA |
| `link_valid` | 제시한 링크가 모두 열리고 내용과 일치하면 Y, 하나라도 문제가 있으면 N, 링크가 없으면 NA |
| `amendment_reflected` | 최근 개정 관련 문항(★)에서 개정 내용을 반영했으면 Y, 아니면 N, ★ 문항이 아니면 NA |
| `confidence_label` | 답변이 스스로 표시한 신뢰도. `확인됨` / `부분확인` / `미확인`, 표시가 없으면 `없음` (A·C 조건은 대부분 `없음`) |

### 오류 감지 가능성 (이 프로젝트의 핵심 지표)

정답률만으로는 "사용자가 정답을 모를 때 AI를 믿어도 되는가"에 답할 수 없습니다. 그래서 **틀린 답(0~1점)을 사용자가 알아챌 수 있었는지**를 따로 측정합니다.

| 지표 | 계산 | 의미 |
|---|---|---|
| **감지 가능 오류율** | 0~1점 답변 중 신뢰도가 `부분확인` 또는 `미확인`인 비율 | 높을수록 좋음. AI가 스스로 경고했으므로 사용자가 추가 확인할 수 있었던 오류 |
| **위험 오답 수** | 신뢰도가 `확인됨`인데 0점인 답변 수 | 0이어야 함. 확신하며 틀린 답으로, [자녀세액공제 사례](../case-studies/01-child-tax-credit.md)와 같은 유형 |
| **과잉 경고율** | 2점 답변 중 신뢰도가 `부분확인`·`미확인`인 비율 | 낮을수록 좋음. 너무 높으면 경고가 의미를 잃음 |

신뢰도 표시가 없는 답변(`없음`)은 사용자에게 아무 경고도 주지 않으므로, 틀렸다면 감지 불가능한 오류로 봅니다.

## 5. 결과 기록과 집계

1. 채점 결과를 [results.csv](results.csv)에 한 행씩 기록합니다. (문항 30개 × 조건 3개 = 최대 90행)
2. 아래 명령으로 요약표를 만듭니다.

```bash
python evaluation/summarize.py
```

3. 생성된 `evaluation/summary.md`의 표를 README의 결과 섹션에 붙여 넣습니다.

## 6. 한계

- **표본 크기**: 30문항은 경향을 보여주기에는 충분하지만 통계적으로 일반화하기에는 작습니다.
- **채점자 1인**: 채점자가 실험 설계자 본인이라 편향 가능성이 있습니다. 정답을 미리 확정하고 원문을 공개해 이를 보완합니다.
- **시점 의존성**: 결과는 특정 기준일과 특정 모델 버전에 대한 것입니다. 법령 개정이나 모델 업데이트 후에는 달라질 수 있습니다.
- **세무 자문 아님**: 이 프로젝트는 AI 답변의 정확도를 검증하는 실험이며, 개별 세무 판단을 대신하지 않습니다.

## 7. 1차 검증 수행 기록

- 범위: ★ 문항 10개 (Q01, Q02, Q04, Q05, Q06, Q07, Q08, Q13, Q17, Q19)
- 모델: Opus 5.5, 노력 '중간'
- 기준일: 2026년 10월 19일 (모든 조건 동일)
- 통제: 수행 기간 동안 메모리 생성, 이전 채팅 검색 및 참조 기능을 끔
- 수행일:
  - A조건: Q01, Q02, Q04, Q05, Q06, Q07, Q08, Q13, Q17, Q19 -> 10/19 수행
  - B조건: Q01, Q02, Q04, Q05, Q06, Q07, Q08 -> 10/19 수행, Q13, Q17, Q19 -> 10/20 수행 (사용 한도로 중단 후 재개, 기준일은 10/19로 통일)
  - C조건: Q01, Q02, Q04, Q05, Q06, Q07, Q08, Q13, Q17, Q19 -> 10/20 수행 (기준일은 10/19로 통일)
- 나머지 20문항은 2차 검증에서 추가 예정
- 수행 방식: 계획(질문마다 새 대화)과 달리, 조건별로 10문항을 하나의 대화에서 연속 질문함.
  세 조건 모두 같은 방식으로 수행해 조건 간 비교 조건은 동일하나, 뒤 문항의 답변이
  앞 문항의 대화 내용을 참고했을 수 있음. 2차 검증에서는 질문마다 새 대화로 수행할 예정.
- 채점 기준 보완: 채점 중 정한 세부 기준은 observations.md의 "채점 기준 결정 사항" 참고.
  특히 조문정확은 정답란에 적은 핵심 조문 기준으로 판단했으며, 부수적으로 인용한 조문은
  검증 범위에서 제외함.
