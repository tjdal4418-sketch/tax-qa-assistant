# 세법 질의응답 도우미 — MCP 연결 전후 환각 검증 프로젝트

> 법령 MCP를 연결한 AI가 세법 질문에 조문 번호와 근거를 함께 제시하도록 설계하고,
> **일반 AI와 비교해 환각이 얼마나 줄었는지 30개 질문으로 직접 채점해 검증한 기록**입니다.

**AI를 쓸 줄 아는 것**에서 끝나지 않고, **AI 결과를 세법 지식으로 검증할 수 있는가**를 보여주는 것이 이 프로젝트의 목적입니다.

---

## 왜 만들었나

AI에게 세법을 물으면 그럴듯한 답이 나오지만, 실무에서 그대로 쓰기 어려운 이유가 세 가지 있습니다.

| 문제 | 설명 |
|---|---|
| 개정 미반영 | 세법은 매년 바뀌는데, AI는 학습 시점 이후의 개정을 모른다 |
| 그럴듯한 근거 | 존재하지 않는 조문 번호나 틀린 수치를 자신 있게 제시한다 |
| 확인 불가 | 출처가 없어 사용자가 직접 검증하기 어렵다 |

법령 MCP(국가법령정보센터 데이터를 AI가 직접 조회하는 도구)를 연결하면 이 문제가 해결될 것이라 기대했지만, 실제로 써보니 **도구를 연결하는 것만으로는 부족**했습니다.

## 출발점이 된 사례

> 📄 자세히: [사례 01. 법령 MCP를 연결했는데도 틀린 답](case-studies/01-child-tax-credit.md)

법령 MCP를 연결한 AI에게 "자녀세액공제 몇 살부터 가능해?"라고 물었더니, 조문 원문까지 인용하며 **"8세 이상"**이라고 답했습니다. 하지만 2026년 4월 소득세법 개정으로 **2026년 귀속분은 조문상 9세 이상, 부칙 특례까지 반영하면 실질적으로 10세부터**였습니다.

| 원인 | 대응 |
|---|---|
| MCP가 '현행'이라고 표시한 법령이 개정 전 버전이었음 | 공포일이 오래됐으면 웹으로 개정 여부 재확인 |
| 연도별 기준이 본문이 아닌 부칙에 있었음 | 조문 조회 시 부칙을 반드시 함께 조회 |
| 아동수당법 개정이 원인이었음 | 연계 법률 검토 단계 추가 |

이 경험을 바탕으로 **검증 절차를 내장한 프로젝트 지침**을 만들고, 그 효과를 체계적으로 측정했습니다.

## 도우미의 작동 방식

> 📄 전체 지침: [prompts/tax-assistant-prompt.md](prompts/tax-assistant-prompt.md)

**검증 절차 (답변 전에 모두 수행)**

1. **법령 특정** — 법률·시행령·시행규칙의 공포일, 시행일 확인
2. **최신성 검증** — MCP의 '현행' 표시를 믿지 않고 최근 개정 여부를 웹으로 재확인
3. **부칙 확인** — 적용례, 경과조치, 연도별 특례 확인
4. **연계 법률 확인** — 중복지원 배제, 특례법 우선 관계 검토
5. **해석 확인** — 필요하면 해석례, 예규, 심판례 확인

**답변 형식** — 한 줄 답 → 핵심 정리 표 → 쉽게 말하면 → 주의할 점 → 근거 조문(클릭 가능한 링크) → 출처 → 검증 메모

**신뢰도 표시** — 모든 답변에 ✅ 확인됨 / ⚠️ 부분 확인 / ❌ 미확인을 붙이고, 조회한 법령의 공포일을 함께 보여줍니다. 사용자가 세법을 몰라도 **날짜와 등급만 보고** 추가 확인이 필요한 답을 알아챌 수 있게 하기 위해서입니다.

## 검증 방법

> 📄 자세히: [evaluation/methodology.md](evaluation/methodology.md)

| 조건 | 설정 |
|---|---|
| A. 일반 AI | 지침 없음, MCP 끔, 웹 검색 끔 |
| B. 도우미 | 프로젝트 지침 + 법령 MCP + 웹 검색 |
| C. MCP만 | 지침 없음 + 법령 MCP만 |

- **질문**: 소득세, 양도소득, 법인세, 부가세, 상증세, 국세기본법 30문항 (절반은 최근 개정 관련)
- **정답 확정**: AI 답변 수집 전에 국가법령정보센터 원문으로 직접 확인
- **채점**: 정답 2점 / 부분 정답 1점 / 오답 0점 + 환각 유형 6가지 분류
- **핵심 지표 — 오류 감지 가능성**: 정답률만으로는 "정답을 모르는 사용자가 믿어도 되는가"에 답할 수 없습니다. 그래서 틀린 답 중 AI가 스스로 경고한 비율(감지 가능 오류율)과, 확신하며 틀린 답의 수(위험 오답)를 따로 측정합니다.
- **통제**: 같은 모델, 같은 기준일, 질문마다 새 대화, 답변 원문 전부 공개

## 결과

> 1차 검증 결과 (★ 최근 개정 문항 10개 기준)

| 지표 | A. 일반 AI | B. 도우미 | C. MCP만 |
|---|---|---|---|
| 평균 점수 (2점 만점) | 1.40 | 2.00 | 1.60 |
| 정답률 | 50% (5/10) | 100% (10/10) | 70% (7/10) |
| 환각 발생 문항 | 50% (5/10) | 0% (0/10) | 30% (3/10) |
| 조문 인용 정확도 | 100% (1/1) | 100% (10/10) | 100% (10/10) |
| 최근 개정 반영률 (★문항) | 70% (7/10) | 100% (10/10) | 90% (9/10) |
| 감지 가능 오류율 | 0% (0/5) | - | 0% (0/3) |
| 위험 오답 수 (확신하며 틀림) | 0 | 0 | 0 |

※ 위험 오답은 '확인됨' 표시 후 틀린 답입니다. A·C는 신뢰도 표시 기능이 없어 0으로 집계되었으나, 틀린 답 8건이 모두 등급 경고 없이 전달되었습니다.

※ 조문 인용 정확도의 분모는 조문을 인용한 문항 수입니다. A는 10문항 중 1문항에서만 조문을 인용했습니다.

## 발견한 점

1차 검증은 최근 개정이 있었던 ★ 문항 10개로 진행했다.

**1. 정답률은 A 50% → C 70% → B 100%였다.**

평균 점수(2점 만점)는 A 1.40, C 1.60, B 2.00이다.

**2. 도구 연결만으로는 부족했다.**

MCP만 연결한 C는 2026년 4월 개정 문항(Q01, Q02)에서 일반 AI와 똑같이 틀렸다. MCP가 '현행'으로 돌려준 법령이 개정 전 버전이었기 때문이다. Q01에서 C는 개정 조문을 조회하고도 현행본과 다르다며 오히려 정답을 배제했다. B는 같은 MCP를 쓰면서도 지침의 최신성 검증 단계로 개정을 찾아냈다. B와 C의 점수 차이가 난 문항(Q01, Q02, Q04)이 곧 검증 절차의 효과다.

**3. MCP는 근거를 제시하는 방식을 바꿨다.**

근거 조문을 제시한 문항은 A 1개, B·C 10개였고, 인용한 핵심 조문은 모두 정확했다. B가 제시한 링크도 모두 유효했다.

**4. O/X 채점이었다면 보이지 않았을 차이가 있었다.**

Q02(95만 원)와 Q04(40만 원)는 세 조건 모두 핵심 숫자를 맞혔다. 하지만 Q02에서 A·C는 공제대상 자녀를 "8세 이상"으로 설명해, 그대로 믿고 자녀 수를 세면 틀린 결과가 나온다. Q04에서도 A는 대상 연령을, C는 종전 한도와 변경 시기를 틀리게 설명했다.

**5. 신뢰도 표시는 위험한 오답을 막았지만, 과잉 경고가 많았다.**

B는 확신하며 틀린 답(위험 오답)이 0건이었다. 다만 정답 10개 중 4개(Q07, Q08, Q13, Q19)에 '부분확인'을 붙였다. 모두 조세특례제한법·법인세법 문항으로, 공식 출처와 교차 확인하지 못한 경우였다. 경고가 너무 잦으면 의미를 잃기 때문에, 신뢰도 기준 조정이 다음 과제다. A·C는 신뢰도 표시 기능이 없어, 틀린 답 8건이 모두 등급 경고 없이 전달됐다.

**6. 한계**

1차는 ★ 문항 10개만 다뤘고, 조건별로 한 대화에서 연속 질문했으며, 채점자는 1인이다. 자세한 내용은 [methodology.md](evaluation/methodology.md)와 [observations.md](evaluation/observations.md)에 기록했다.

## 한계

- 30문항은 경향을 보기엔 충분하지만 통계적으로 일반화하기엔 작습니다.
- 채점자가 실험 설계자 본인입니다. 정답을 사전에 확정하고 답변 원문을 공개해 이를 보완했습니다.
- 결과는 특정 기준일과 모델 버전에 대한 것입니다.
- 이 프로젝트는 AI 답변의 정확도를 검증하는 실험이며, 세무 자문이 아닙니다.

## 직접 재현하기

1. Claude에서 새 프로젝트를 만들고 [프로젝트 지침](prompts/tax-assistant-prompt.md)의 코드 블록을 붙여 넣습니다.
2. 법령 MCP 커넥터를 연결하고 웹 검색을 켭니다.
3. [questions.md](evaluation/questions.md)의 질문을 조건별로 새 대화에서 입력하고, 답변을 `evaluation/raw/`에 저장합니다.
4. [채점 기준](evaluation/methodology.md#4-채점-기준)에 따라 `results.csv`에 기록합니다.
5. `python evaluation/summarize.py`를 실행해 요약표를 만듭니다.
