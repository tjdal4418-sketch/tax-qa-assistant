# 사례 01. 법령 MCP를 연결했는데도 틀린 답 — 자녀세액공제 연령

> **요약:** 법령 MCP를 연결한 AI가 "현행"이라고 표시된 법령을 조회해 답했지만, 그 버전은 이미 개정 전 법이었다. 세법 지식으로 이상한 점을 발견해 재검증했고, 이 경험을 바탕으로 도우미의 검증 절차를 설계했다.

## 1. 질문

> 자녀세액공제 몇 살부터 가능하지? (조회일: 2026년 10월 19일)

## 2. AI의 첫 답변 — 오답

| 항목 | 내용 |
|---|---|
| 조건 | 법령 MCP 연결, 별도 지침 없음 (검증 조건 C에 해당) |
| MCP가 반환한 법령 | 「소득세법」 [현행] — 2025.12.23. 공포본 |
| AI의 답 | **8세 이상**부터 가능 |
| 채점 | **0점 (오답)** · H1(구법 적용), H6(부칙 특례 누락) |

AI는 조문 번호(제59조의2제1항)와 원문을 정확히 인용했습니다. 형식만 보면 근거가 확실한 답변이었기 때문에, 세법 개정 흐름을 모르면 틀린 줄 알기 어려웠습니다.

## 3. 오류를 발견한 과정

2026년에 아동수당 지급 연령이 확대되었다는 사실을 알고 있었고, 자녀세액공제 연령 기준은 과거에도 아동수당과의 중복을 피하기 위해 함께 조정되어 왔다는 점을 떠올렸습니다. 그래서 다음과 같이 다시 질문했습니다.

> 아동수당 연령 확대되어서 올해 실질적으로 10세부터 가능하지 않아?

## 4. 재검증 결과 — 정답

| 구분 | 내용 |
|---|---|
| 근거 법률 | 소득세법 일부개정 (법률 제21548호, 2026.4.21. 공포·시행) |
| 본문 | 제59조의2제1항의 "8세 이상" → "13세 이상" |
| 부칙 제2조 | 2026~2029년은 연도별 특례: 2026년 9세, 2027년 10세, 2028년 11세, 2029년 12세 이상 |
| 추가 특례 | 2017년생은 2026~2029년 아동수당 대상이므로 자녀세액공제 적용 배제 |
| **실제 결론** | **조문상 9세 이상이지만, 2017년생(9세)이 빠지므로 2026년에는 실질적으로 10세(2016년생)부터** |

## 5. 원인 분석

| 원인 | 설명 |
|---|---|
| ① MCP의 '현행' 표시가 최신이 아님 | 조회일보다 약 10개월 전 공포본을 현행으로 반환했고, 4월 개정이 반영되지 않았다 |
| ② 조문 본문만 확인 | 연도별 기준은 본문이 아니라 부칙에 있었는데, 부칙을 확인하지 않았다 |
| ③ 연계 법률 미고려 | 아동수당법 개정이 소득세법 개정의 원인이었지만 이를 함께 보지 않았다 |

## 6. 도우미 설계에 반영한 것

| 원인 | 프로젝트 지침에 추가한 절차 |
|---|---|
| ① | **2단계 최신성 검증** — MCP 공포일이 오래됐으면 웹으로 개정 여부를 반드시 재확인 |
| ② | **3단계 부칙 확인** — 조문 조회 시 부칙(적용례·경과조치·특례)을 함께 조회 |
| ③ | **4단계 연계 법률 확인** — 중복지원 배제, 특례법 우선 관계 등을 검토 |
| 사용자가 몰랐다면? | **신뢰도 등급 + 공포일 표시** — 세법 지식 없이도 "10개월 전 공포본, 최근 개정 미확인 ⚠️"라는 신호로 의심할 수 있게 |

## 7. 배운 점

- **도구 연결이 정확성을 보장하지 않는다.** MCP는 환각을 줄이는 수단이지만, 도구가 돌려준 데이터 자체가 오래되었을 수 있다.
- **"근거가 있어 보이는 오답"이 가장 위험하다.** 조문 번호와 원문이 정확히 인용된 답은 의심받기 어렵다.
- **결국 결과를 검증할 수 있는 도메인 지식이 필요하다.** 이 오류는 세법 개정 흐름을 알고 있었기 때문에 발견할 수 있었다.
- **그렇다면 도메인 지식이 없는 사용자는?** 이 질문에서 "오류 감지 가능성" 지표가 나왔다. 오류를 0으로 만들 수 없다면, 적어도 틀린 답이 스스로 경고 신호를 내도록 설계해야 한다.
